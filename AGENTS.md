# Brief for anyone (human or AI) working on TimeLock

TimeLock is a Manifest V3 extension (Chrome/Brave/Edge 120+). Plain JS, no build step, no dependencies.

- **Tracking** is in `src/background.js`. `chrome.storage.session.cur` holds `{host, since}`; every tab/focus/idle event and a 30 s alarm call `flush()`, which adds the elapsed seconds to `usage:<YYYY-MM-DD>` and re-reads the front tab. Gaps over 90 s are dropped (the computer slept). Everything runs through the `serial()` queue so events can't double-count.
- **Blocking** uses `declarativeNetRequest` dynamic rules (one per locked limit) that redirect main-frame loads to `app/blocked.html#<original URL>`, plus `tabs.update` for tabs already open. Locked state is always derived from usage + `unlocks` + settings in `core.ruleStatus`; nothing stores "locked".
- **Away detection:** `chrome.idle` (60 s, system-wide) pauses counting unless `tab.audible` or the page's content script reported a playing `<video>/<audio>` (`media` message → `storage.session.media:<tabId>`). The clock mirrors this locally with its own last-input time.
- **Countdown clock:** shown only on sites in `settings.clockSites` (toggled by the popup's Show timer buttons via `setClock`, never needs the password). Counts down on limited sites, up on the rest. `src/content.js` (plain script, Shadow DOM) asks the background for `pageStatus` every 15 s and on focus/visibility changes, and ticks locally in between only while the tab is visible and focused. It's draggable; positions are saved per hostname in `storage.local.clockPos` as an offset from the nearest edges.
- **Goals** (`settings.goals`: `{kind: "site"|"app", name, min, max}` in minutes) are soft: never locked, excluded from `isTightening`. One colour rule, `core.goalState` (under/met/near at 75% of max/over), re-implemented in `content.js`, the Mac app's `BrowserSnapshot.Goal.state` and the plugin's `data.goalState`; keep all four in step. Site goals count subdomains together. Goals reach the Mac app and Stream Deck through `browser.json`.
- **Stats page** (`app/stats.*`): one `history` request returns this year + 30 days of `usage:<day>` plus Mac app days from the connector's `history` message; everything else is computed client-side with `core.daysBetween/rangeStart/bucket/weekStart` (weeks start Monday). Ranges start at the first tracked day. Preview with `/tests/stats-harness.html`.
- **Pure logic** (days, matching, status, tighten-vs-loosen, validation) is in `src/shared/core.js`, covered by `node tests/core.test.mjs`. Run it after any change there.
- **Password:** salted PBKDF2 hash in `storage.local.pw`; `verify()` enforces the cooldown in `core.cooldownMs`. Never store or log the password.
- **Errors:** every user-facing error has a `TL-###` code from `src/shared/errors.js`, documented in `ERRORS.md`. `scripts/check-errors.sh` enforces this. Never reuse or renumber a code.
- **UI preview** without installing: serve the repo root (`python3 -m http.server 8792`) and open `/tests/ui-harness.html`, which fakes `chrome.*` and the background.
- **Mac app** (`mac/`, Swift, no Xcode: `mac/build.sh`): a menu bar tracker (`Tracker.swift`: frontmost app every 2 s, `CGEventSource` idle time, `IOPMCopyAssertionsByProcess`: the app's own display-sleep assertions = video, its own system-sleep assertions = sound (never coreaudiod's "created for PID" or Core Audio's IsRunningOutput: VLC keeps its stream open while paused and DAWs all day); sound only counts for `Tracker.mediaPlayers`/`browsers`, `CGSessionCopyCurrentDictionary` = screen locked). The same executable is the native messaging host: launched with a `chrome-extension://` argument it runs `Connector.run()` (4-byte LE length + JSON on stdin/stdout) and exits. Shared data: `~/Library/Application Support/TimeLock/apps/<day>.json` (written only by the menu bar app) and `browser.json` (written only by the connector). Files are replaced with write-temp-then-rename, never `.atomic` (that stages outside the folder).
- **Menu → popup** ("Open TimeLock in the Browser"; a plain click shows the menu, Jon's choice): the menu bar app writes `open-popup.request`, the extension's long-lived `connectNative` port (`listenToMac`, message `listen`) has the connector claim it by rename and push `openPopup`; the extension calls `chrome.action.openPopup` (falls back to a tab, `popup.html?full`) and answers `popupOpened`, which becomes `open-popup.ack`. Requests older than 15 s are dropped.
- **Connection:** the extension's ID is pinned by `"key"` in manifest.json (`jhoilplbkfpfihboddmplmbblcenmapn`); `BrowserLink.extensionID` must match. `background.js macSync()` calls `sendNativeMessage("com.jonpike.timelock", {type:"sync", …})` at most every 25 s and stores the reply in `apps:<day>` and `mac`. "Host not found" just means the app isn't installed.
- **Stream Deck plugin** (`streamdeck/com.jonpike.timelockdeck.sdPlugin`, plain Node, `ws` vendored): read-only; polls `status.json` (Mac app, every 2 s; stale after 30 s = not running), `browser.json` and `apps/<day>.json`, recomputes limit totals in `bin/data.js`, draws SVG keys in `bin/render.js`. Test with `node streamdeck/tools/test.js`; install with `streamdeck/install.sh`.
- **Releases:** the extension, Mac app and Stream Deck plugin always share one version, kept in the top-level `VERSION`. Bump all three with `scripts/set-version.sh X.Y.Z` (never edit the manifests or `mac/VERSION` by hand; `scripts/check-versions.sh` fails both release builds if they drift). Write `RELEASE_NOTES.txt` (extension) and `mac/RELEASE_NOTES.txt` (Mac app), say "no changes" for a part that didn't change, push to `main`: `release.yml` builds `updates/`, `mac-release.yml` builds `updates/mac/` on a Mac runner, and `streamdeck/install.sh` installs the plugin. Never edit `updates/` by hand.
